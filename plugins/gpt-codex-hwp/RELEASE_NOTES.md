# Gpt_Codex_HWP v0.2.5 릴리즈 노트

- 상태: 정식 릴리즈
- 작성일: 2026-08-10
- 검증 기준: Windows x64 개발·실문서 검증, macOS Apple Silicon 실제 기기 미검증

[English](RELEASE_NOTES.en.md) | [README](README.md)

## 개요

v0.2.5는 v0.2.2의 HWP 읽기 전용·HWPX 쓰기 원칙, Codex 관리 캐시 밖의 명시적 지속 런타임 설치와 내부 one-shot 도구 계약 9개를 그대로 유지합니다. 불변 `v0.2.3`과 `v0.2.4` 태그는 hosted Windows 릴리스 게이트의 실행 이식성 문제를 확인한 뒤 미게시 후보로 보존했으며, 어느 태그에도 GitHub Release나 배포 자산을 만들지 않았습니다. v0.2.5는 같은 전체 테스트 범위를 파일별 제한·격리 실행으로 전환합니다. v0.2.4 후보 대비 사용자 런타임·도구·문서 동작은 바뀌지 않습니다.

## 주요 변경 사항

- 릴리스 Node 게이트가 루트 테스트 26개와 소스 테스트 41개의 정확한 전체 목록을 파일별로 제한·격리 실행합니다. 테스트를 삭제하거나 검증 범위를 줄이지 않았고, 누락·중복·예상 밖 파일은 fail-closed로 거부합니다.
- 각 파일의 출력·실행 시간·종료 시간을 제한하며 실패 시 허용된 고정 영수증만 남깁니다. 원시 TAP, 오류, 사용자 경로, PID, 환경 변수와 문서 내용은 공개하지 않습니다.
- Windows에서 제한 종료가 필요하면 기존의 하위 프로세스 트리 종료기를 재사용하고 자식 close와 종료 완료를 모두 확인합니다. 일반 Node 테스트와 SVG 진단을 포함한 모든 격리 경로에 같은 규칙을 적용합니다.
- 합성 Git 이력의 심볼릭 링크 모드 검증이 호스트의 `core.symlinks` 설정에 좌우되지 않도록 해당 임시 저장소의 checkout 명령만 이식 가능하게 만들었습니다. 실제 Git 트리의 `120000` 모드 검사는 유지합니다.
- hosted runner가 제공하는 별칭 임시 경로를 검증된 canonical 임시 루트로 정규화하고, 환경과 경로 길이에 따라 달라지는 stderr 바이트 수는 기존 `1`부터 `65,537`까지의 경계로 검증합니다.
- 관리 플러그인 캐시 밖의 전체 플러그인 버전·플랫폼·아키텍처·Node 주버전별 경로에 검증된 런타임을 원자적으로 설치합니다. 같은 Codex 프로필의 Node 22와 Node 24가 서로의 런타임을 교체하지 않으며, 캐시가 재생성되어도 같은 런타임을 다시 사용합니다. 문서 작업 중에는 설치나 네트워크 접근을 하지 않습니다.
- worker-only·child-only·mixed 종료 영수증을 모두 fail-closed로 집계하고 감독된 나머지 프로세스 트리가 0개인지 검증합니다.
- 소스와 생성 런타임 잠금 파일을 `fast-uri 3.1.5`, `hono 4.13.1`, `ip-address 10.4.0`으로 갱신했으며 두 production audit 모두 알려진 취약점 0개입니다.
- Windows 고부하·콜드 스타트에서 PowerShell ACL 헬퍼가 조기 실패하지 않도록 대기 상한을 15초로 조정했습니다. 적용하는 DACL과 허용 주체는 바꾸지 않았습니다.
- 공개 안정판 설치 안내를 v0.2.5와 기본 one-shot 구조에 맞췄습니다. 기본 설치는 `/mcp`에 영구 `gpt-codex-hwp` 서버를 등록하지 않습니다.
- v0.2.2 공개 릴리스와 미게시 v0.2.3·v0.2.4 후보 태그는 변경하지 않았으며 v0.2.5는 새 빌드 ID를 사용합니다.

## 검증 증거

- 공개 v0.2.2 ZIP의 SHA-256을 공개 `SHA256SUMS`와 대조했습니다.
- 새 디렉터리 콜드 설치에서 doctor 필수 검사 11/11, 실제 HWP 감지·읽기, HWPX 생성·독립 검증을 통과했습니다.
- Codex 공용 설치 경로의 v0.2.2에서도 설치 런타임 one-shot으로 HWPX를 생성·검증했고 감독된 나머지 하위 프로세스 0개를 확인했습니다.
- 병렬 저장소 테스트 실패를 로컬에서 재현했고, 런타임 의존성 복원 후 해당 스모크 28/28 통과로 공유 트리 경합을 확인했습니다.
- 격리된 Codex 홈에서 런타임을 설치한 뒤 관리 캐시를 의존성 없이 다시 만들고 doctor와 실제 HWPX 생성·검증을 재실행해 설치 영수증 해시가 바뀌지 않음을 확인했습니다.
- 간헐 실패하던 캐시 재생성 회귀 테스트를 수정 후 3회 연속 통과시켰습니다.
- 한 Codex 홈에서 Node 22와 Node 24의 런타임 경로가 분리되고 한쪽 설치가 다른 쪽 디렉터리를 변경하지 않는 회귀 테스트를 추가했습니다.
- worker-only·child-only·mixed one-shot 정리 경로에서 유효한 영수증을 집계하고 감독된 나머지 프로세스 트리 0개를 확인했습니다.
- 최종 정체성의 로컬 권위 실행기에서 루트 Node 테스트 파일 26개와 소스 Node 테스트 파일 41개를 모두 통과했습니다. 릴리스 아티팩트 생성·업로드와 attestation은 같은 불변 태그에 대한 전체 릴리스 게이트가 성공한 뒤에만 실행됩니다.

## 사용자 자원 사용 안내

미사용 시 상주 Gpt_Codex_HWP Node 프로세스는 0개입니다. 저장소 테스트 직렬화는 CI와 개발 검증의 동시 Node 프로세스 수를 낮추지만 사용자 문서 작업의 고정 RSS 또는 설치 크기 감소를 뜻하지 않으며, 고정 RSS 감소율이나 설치 크기 감소는 주장하지 않습니다.

## 설치와 업그레이드

v0.2.5를 설치할 때는 설치 결과의 `installedPath`를 경로·플러그인 identity 규칙으로 먼저 검증한 뒤 그 경로에서 실행합니다.

```powershell
node dist/install-runtime.js --json
node dist/doctor.js --json
```

첫 명령은 JSON `code` `RUNTIME_INSTALL_OK`를 반환해야 합니다. 실행 중인 모든 Codex CLI와 Desktop 호스트를 완전히 닫았다가 다시 여십시오. 문서 작업 하나를 실행해 성공했는지 확인하고 생성 결과를 검증한 뒤 one-shot 프로세스와 그 하위 프로세스가 종료되는지 확인하십시오. 문서 작업은 설치를 자동 수행하지 않으므로 `RUNTIME_NOT_INSTALLED`면 검증한 `installedPath`에서 설치기를 명시적으로 다시 실행합니다. v0.2.2의 관리 캐시 내부 직접 설치는 캐시 재생성 뒤 유지되는 방식이 아니었으므로, v0.2.5 재시작 검증 전에는 기존 작동 버전을 제거하지 마십시오.

운영 의존성은 `$CODEX_HOME/plugin-runtime-data/gpt-codex-hwp/<전체-플러그인-버전>/<platform>-<arch>-node<Node-주버전>`에 남습니다. 플러그인을 제거한 뒤 정리하려면 모든 Codex 호스트를 종료하고 더 이상 사용하지 않는 정확한 전체 플러그인 버전 디렉터리만 수동으로 제거하십시오. 자동 재귀 삭제 명령은 이번 릴리즈에 포함하지 않습니다.

## 호환성과 알려진 제한

- Windows x64에서 개발하고 실제 HWP/HWPX 기능을 검증했습니다.
- macOS Apple Silicon은 호환 대상이지만 실제 Mac 기기의 Codex Desktop·한컴오피스 한글에서 검증하지 않았습니다.
- HWP 5.x는 읽기 전용이며 생성·편집 결과는 HWPX입니다. HWP 3.x는 실제 fixture가 없어 보장하지 않습니다.
- 100 MiB까지 CI 검증 범위이며 100 MiB 초과 512 MiB 이하는 비보장 best-effort입니다. 512 MiB 초과는 거부합니다.
- 보호·암호화·서명·DRM 문서는 우회하지 않습니다.
- 글꼴 파일은 포함·설치·내장하지 않습니다.
